# GPX 去重与恢复

本功能针对一个运动者的 GPX 归档，保留原始文件和全部数据库记录，
使用可撤销的 `activities.duplicate_of` 标记决定哪些记录参与统计。
公开提交只包含通用代码、合成测试数据和使用说明，不附带个人运动审计结果。

## 原有问题与修复

原导入器按 `imported.json` 中的文件名跳过已处理文件，再用首个 GPS 点的毫秒时间戳
作为 `run_id`。同一次运动的不同导出若文件名和首个点时间不同，就会产生不同数据库行。
JSON 和 SVG 原先会把这些行全部累加；文件名清单本身无法判断真实运动是否相同。

- 每次 GPX 同步重新审计全部源文件，包括已导入的文件。无新文件时也能修复历史统计。
- 数据库所有原有行和字段保留，只增加 `duplicate_of`。同一事务中设置或恢复标记。
  网页 JSON、TUI、数据库生成的 SVG、CSV、Parquet 只统计没有排除标记的记录。
- `imported.json` 保留已处理过的全部源文件名，包括重复副本。数据库提交成功后才原子写入清单；
  清单有记录但数据库缺行时重新导入，支持从 GPX 重建空数据库。
- 判定结果写入本地 `gpx_dedup_report.json`，包含文件哈希、指标、别名和排除 ID。
  此文件已加入 `.gitignore`，不会被现有同步工作流的 `git add .` 自动发布。

## 保守判定

自动合并要求运动类型相同、起止时间分别相差不超过 60 秒、时段重叠至少 95%、
距离差不超过 3%、运动时长差不超过 5%，同时满足足够的 GPS 点数、时段覆盖和空间接近程度。
具体阈值见 `run_page/gpx_dedup.py` 的 `POLICY`。

时间对齐后每 5 秒采样，空间差中位数不得超过 15 米、95 分位不得超过 30 米。
共同 GPS 时段至少覆盖重叠活动时段的 80%，有效采样覆盖率至少 90%。
不跨长 GPS 空档或不同分段插值；同秒采样只允许合并相距不超过 5 米的点。

没有 GPS 的近似记录仅提示复核，原统计保留；字节内容完全相同的改名副本可以识别。
不按同一天、同一路线或相似距离单独判重，也不会由 A≈B、B≈C 自动推断 A≈C。
默认保留开始时间最早的文件，同时间按文件名稳定排序；这不代表其设备精度必然更高。

不同活动若碰巧共享旧时间戳 ID，会停止同步，避免原有 upsert 静默覆盖。
损坏或无时区的时间数据、过期人工确认以及数据库对应关系不一致也会停止处理。
本补丁没有更换整个数据库的 ID 规则。

多人同行的轨迹可能接近。如果归档包含他人的运动，应明确使用 `keep_separate`，
而不能仅靠轨迹推断运动者身份。上传端最好保留稳定运动 UUID、原始来源与设备信息；
源文件没有这些信息时，检测器不能证明是哪个设备或应用造成重复。

## 审计和应用

在仓库根目录安装项目依赖后，只读审计：

```sh
python run_page/gpx_dedup.py --report /tmp/gpx-audit.json
python -m unittest discover -s tests -p 'test_gpx_dedup.py' -v
```

应用标记并重新导出网页数据（沿用现有隐私配置）：

```sh
IGNORE_BEFORE_SAVING=True IGNORE_START_END_RANGE=200 python run_page/gpx_sync.py
```

现有 `Run Data Sync` 工作流随后生成 SVG 和部署页面。
修改 `gpx_dedup_overrides.json` 也会触发该同步流程。
本地审计报告可能包含个人运动元数据，分享前应单独审阅。

## 人工例外与撤销

要让某一对恢复分别计入，编辑 `gpx_dedup_overrides.json` 后重新同步：

```json
{
  "enabled": true,
  "decisions": [
    {
      "files": ["first.gpx", "second.gpx"],
      "action": "keep_separate"
    }
  ]
}
```

文件名应替换为真实文件名。将 `enabled` 设为 `false` 后重新同步，
可清除此功能的统计排除标记。无需删除 GPX 或导入清单。

经运动者确认的缺 GPS 重复可以使用 `action: "merge"`，同时指定 `canonical` 文件名
和与 `files` 顺序对应的两个 `sha256` 值（从本地审计报告复制）。
启用时哈希不匹配则拒绝应用，避免文件变化后沿用过期决定。

## 回归测试

测试全部使用临时目录和合成轨迹，不上传或改动真实运动源数据。
覆盖同日多次运动、隔日同路线、不同类型/位置、部分重叠、缺失和稀疏 GPS、分段空档、
同秒冲突和取整采样、静止占位轨迹、时区、改名副本、非传递匹配、重复同步、先后上传、
空库重建、事务失败、旧库迁移、人工例外及恢复、JSON/SVG 一致性。
